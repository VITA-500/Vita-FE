# Testing

VITA FE는 Phase 1부터 Vitest와 Testing Library 기반 자동화 테스트를 사용한다.

## Commands

```bash
npm run test
npm run lint
npm run build
```

PR 전에는 위 세 명령을 기본 검증으로 실행한다.

권장 전체 검증:

```bash
npm ls --depth=0
npx prettier --check .
npx eslint . --max-warnings 0
npx tsc --noEmit
npx vitest run
git diff --check
```

## Test Scope

| Type      | Scope                                                                  |
| --------- | ---------------------------------------------------------------------- |
| Unit      | API wrapper, token storage, service URL 생성, 순수 helper              |
| Component | 인증 상태별 UI, 모달, 버튼 동작, 비로그인/로그인 분기                  |
| Manual QA | OAuth provider 로그인, 배포 redirect URI, 실제 백엔드 세션/cookie 흐름 |

## Current Coverage

- `requestJson`
  - base URL 조합
  - `credentials: "include"`
  - API error 변환
  - empty response 처리
- `tokenStorage`
  - auth hint 저장/삭제
- `authService`
  - OAuth authorization URL 생성
- `AuthProvider`
  - guest ready 상태
  - auth hint 기반 사용자 로드
  - 401 발생 시 auth hint 제거
- `GuestNewChatDialog`
  - 비로그인 새 상담 안내 문구
  - 닫기/채팅 지우기 액션

## Testing Rules

- UI 테스트는 사용자에게 보이는 label, role, text를 우선 사용한다.
- 구현 세부 class에 강하게 의존하지 않는다.
- 단, 강조 스타일처럼 명시적인 UX 요구가 있는 경우에만 class를 확인한다.
- OAuth 실제 provider 흐름은 외부 서비스와 redirect URI에 의존하므로 자동화하지 않는다.
- 새 인증/공통 API 로직을 추가하면 최소 1개 이상의 회귀 테스트를 함께 추가한다.

## Admin Manual QA

BE 계약에 맞춰 관리자 화면은 저장 성공 여부뿐 아니라 입력 차단, 오류 위치, 상태 갱신까지 확인한다.

### 요금제 관리

| ID  | 시나리오                                | 기대 결과                                              |
| --- | --------------------------------------- | ------------------------------------------------------ |
| P01 | 필수값을 비운 채 저장                   | 토스트가 아닌 오류 블록이 표시되고 오류 위치로 이동    |
| P02 | 금액·연령·속도·제공량 필드에 `-` 입력   | 마이너스 기호가 입력되지 않고 음수 입력 불가 안내 표시 |
| P03 | 최소 연령을 최대 연령보다 크게 입력     | 저장되지 않고 관계 오류가 표시되며 오류 블록으로 이동  |
| P04 | 대상 그룹과 연령 범위를 맞지 않게 입력  | 대상별 허용 연령 오류가 표시되고 저장되지 않음         |
| P05 | 데이터 정책을 제한으로 선택             | 데이터 정책·기본 데이터·소진 후 속도가 한 행에 표시    |
| P06 | 음성·문자 정책을 제한으로 선택          | 각 정책과 제공량 필드가 같은 행에 표시                 |
| P07 | 제한 정책의 제공량을 비운 채 저장       | 해당 제공량 오류가 표시되고 오류 영역으로 자동 이동    |
| P08 | 무제한 정책에 제한값이 남은 상태로 저장 | 저장되지 않고 제한값 제거 안내 표시                    |
| P09 | 수정 모달을 열고 기존 값을 변경         | 등록과 동일한 검증이 적용되고 저장 후 목록이 즉시 반영 |

### 대리점·제휴점 관리

| ID  | 시나리오                              | 기대 결과                                                                                    |
| --- | ------------------------------------- | -------------------------------------------------------------------------------------------- |
| S01 | 위도에 -90 미만 또는 90 초과 입력     | `위도는 -90에서 90 사이로 입력해 주세요.`가 필드 하단에 표시                                 |
| S02 | 경도에 -180 미만 또는 180 초과 입력   | `경도는 -180에서 180 사이로 입력해 주세요.`가 경도 필드에 표시되고 위도 문구는 표시되지 않음 |
| S03 | 운영시간 선택기 열기                  | 시작·종료 중 하나만 열림                                                                     |
| S04 | 시간의 분까지 선택                    | 선택 패널이 자동으로 닫힘                                                                    |
| S05 | 종료 시간을 시작 시간보다 빠르게 선택 | 저장되지 않고 `종료 시간은 시작 시간보다 늦게 입력해 주세요.` 표시                           |
| S06 | 운영시간 오류 상태에서 저장           | 운영시간 영역으로 자동 스크롤되고 오류 문구 확인 가능                                        |
| S07 | 모바일 폭에서 운영시간 입력           | 시작·종료 필드가 세로로 배치되고 겹치지 않음                                                 |
| S08 | 위도·경도·운영시간을 수정 후 저장     | BE 형식에 맞는 값만 전송되고 저장 후 목록이 갱신됨                                           |

### 회원 관리

| ID  | 시나리오                   | 기대 결과                                                         |
| --- | -------------------------- | ----------------------------------------------------------------- |
| U01 | 활성 회원의 정지 버튼 클릭 | 정지 확인 모달이 열리고 위험 액션 스타일로 표시                   |
| U02 | 사유 없이 정지 확인        | `변경 사유를 입력해야 처리할 수 있어요.`가 표시되고 API 요청 없음 |
| U03 | 사유 입력 후 정지 처리     | 상태 배지·버튼·요약 수치가 새로고침 없이 갱신                     |
| U04 | 정지 회원의 정지 해제 클릭 | 정지 해제 모달과 초록색 액션 스타일이 표시                        |
| U05 | 사유 입력 후 정지 해제     | 목록 상태가 즉시 활성으로 변경되고 요약 수치 반영                 |
| U06 | 정지 계정으로 로그인 시도  | 현재 BE 계약상 `INVALID_CREDENTIALS`의 공통 안내가 표시됨         |

정지 계정만 별도 안내하려면 BE가 계정 존재 노출 방지 정책을 변경하고 별도 오류 코드 또는 안내 계약을 제공해야 한다.

### 공통 회귀 확인

- 등록과 수정 모달 모두 동일한 검증이 적용되는지 확인한다.
- 오류 블록과 필드 하단 보조 문구가 중복 표시되지 않는지 확인한다.
- 오류가 현재 스크롤 위치와 관계없이 사용자에게 보이는 위치로 이동하는지 확인한다.
- 저장 실패 후 입력값과 오류 상태가 유지되는지 확인한다.
- 관리자 API 실패 시 BE 오류 메시지가 사용자 안내 영역에 표시되는지 확인한다.
