작성 기준: 2026-10-17, 브랜치 `feat/fe2-map-category-reload`의 커밋 전 변경. 실제 로그인(이메일·소셜)과 배포 환경은 검증하지 않았다. 아래 체크리스트로 확인한다.

## 2. 코드상 QA 주의점

- 복원은 화면을 띄운 뒤 sessionStorage를 읽어 패널을 다시 그린다(hydration 불일치 방지). 복원할 때 아주 짧게 기본 목록이 보였다가 바뀔 수 있다.
- 복원 직후에는 되살린 매장 묶음이 그대로인 동안 핀 자동 맞춤을 하지 않는다. 그래서 가장자리 핀이 목록 패널·바텀시트에 가려진 채로 남을 수 있다.
- 드래그 검색 직후 2.5초 동안도 핀 자동 맞춤을 하지 않는다. 같은 이유로 핀이 가려질 수 있다.
- 복원 중에는 내 위치 기준 자동 조회와 내 위치로 지도 이동을 하지 않는다. 내 위치 버튼, 영업시간 필터 변경처럼 사용자가 직접 바꾸면 원래대로 동작한다.
- 길찾기 상태와 페이지 번호는 저장하지 않는다(돌아오면 1페이지, 길찾기 없음).
- 제휴 혜택 탭은 탭과 혜택 카테고리만 저장한다. 제휴 매장 목록은 다시 조회한다.
- 채팅 답변의 지도 블록에서 "로그인하기"를 누르면 그 채팅 주소로 돌아온다. 지도 상태 저장은 매장 지도 화면에서만 한다.
- 레벨 7 이상으로 축소하면 화면이 반경 5km보다 커서, 화면 모서리 매장은 여전히 조회되지 않을 수 있다.

## 3. QA 시나리오

준비: 이메일 계정 A, 소셜 계정(카카오·구글·네이버), 게스트(로그아웃 상태). 데스크톱과 모바일(실기기 또는 DevTools 375px). 개발자도구 Network 탭에서 `nearby`로 필터해 두면 조회 횟수를 바로 볼 수 있다. 모바일 실기기의 길찾기는 위치 권한이 필요하므로 https 주소(배포 환경)로 확인한다.

### A. 카테고리 검색 중 드래그 재검색

모두 상담·서비스 뱃지를 1개 이상 고른 상태에서 시작한다.

| ID  | 절차                                                  | 기대 결과                                                                    |
| --- | ----------------------------------------------------- | ---------------------------------------------------------------------------- |

| A02 | 천천히 끌다가 누른 채 1초 멈춘 뒤 놓기                | A01과 같음                                                                   |
